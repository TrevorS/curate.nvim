§1 · ARCHITECTURE SPINE

The data layer (P0) — get this right or everything rots

Three non-negotiables, drawn directly from what reading NicolasGB's source taught us.

EXEC
Argv arrays via vim.system({"jj",…}) — no shell, no quoting bugs. Async with callbacks; a raw-stdout variant that preserves NUL bytes for templates.
IDENTITY
Anchor everything — buffers, marks, op refs — on change_id. Never commit_id, never bookmark. Survives rewrites mid-session.
READ MODEL
One template, NUL/control-byte separated fields. Never scrape graph glyphs or human output. Graph topology comes from parent change-ids, computed by us.
the one read query — parse this, nothing else
jj log --no-graph --color=never -r <revset> -T '
  change_id                       ++ US ++
  commit_id.short(8)              ++ US ++
  author.email()                  ++ US ++
  committer.timestamp().ago()     ++ US ++
  description.first_line()        ++ US ++
  parents.map(|c| c.change_id())  ++ US ++   # graph edges
  if(conflict,"C","") ++ if(divergent,"D","") ++ if(immutable,"I","")
  ++ RS
'
US = \x1f (unit sep)   RS = \x1e (record sep)   — bytes that cannot occur in the data

Split stdout on \x1e → records; each on \x1f → fields. The parents field gives the DAG edges; we lay out the graph ourselves so a custom theme or glyph set never breaks parsing. Refresh on g, and debounced (~80ms) after any mutation.

§3 · ROUTE ★ — THE DIFF-EDITOR

How curate becomes jj's diff & merge editor

This is the wedge. The protocol below is jj's real diff-editor contract — the same one that powers split -i, squash -i, and diffedit — so building it once unlocks all of ROUTE.

registration — point jj's diff-editor at a thin launcher that talks to the running nvim
# curate injects these --config flags on every interactive call:
--config ui.diff-editor=curate
--config merge-tools.curate.edit-args=["$left","$right"]
--config merge-tools.curate.program="curate-diff-shim"

# curate-diff-shim: a ~20-line script. It does NOT open its own editor —
# it connects to the already-running nvim via $NVIM (the RPC socket),
# tells it to open the hunk buffer on $left/$right, then blocks on exit code.
THE PROTOCOL — what jj hands us, what we hand back
1
jj materializes two dirs: $left (the "before" tree) and $right (a writable copy of the "after" tree), then invokes our program and blocks.
2
curate opens the hunk-selection buffer, diffing $left ↔ $right. Every hunk starts selected (= included in the result).
3
The user toggles hunks off. On <CR> curate edits $right in place: for every deselected hunk, revert that region of the file back to its $left content. Selected hunks stay.
4
curate exits 0. jj snapshots $right and records the diff. On q we exit non-zero → jj cancels cleanly, nothing changes.
Why this beats the git-shim: no temp git repo, no intent-to-add dance. We edit a directory jj already prepared and exit. NicolasGB's cp-as-merge-tool trick is the non-interactive special case of this same contract (write one file, exit) — we generalize it to interactive per-hunk selection.
ONE BUFFER, FOUR MODES
Same UI; only the target semantics and statusline label change.
SPLIT — selection = the first change
SQUASH-i — selection moves into the target
DIFFEDIT — selection = new content of @
RESTORE — selection = reverted from parent
EDGE CASES (v1)
• zero hunks selected → abort cleanly, no empty change
• binary / un-diffable file → file-level toggle only
• immutable target → confirm prompt before launch
• partial-line selection → out of v1 (hunk is the atom)
• encoding: reuse the UTF-16/32 + BOM round-trip

§5 · ROUTE — SQUASH

Three grains of squash

s
whole @ into its parent. The 80% case — one key, with the u safety net.
S
interactive — opens the diff-editor in SQUASH-i mode; selected hunks move into the target.
m → s
mark a target first, then s squashes into the mark instead of the parent. Live highlight on the destination as you move.

Borrowed from NicolasGB: the live destination highlight while choosing a target. Hosted inside our transient grammar, not a one-off mode.

§6 · NAME

Describe & seal

d — describe
git-style message buffer (changed files shown, syntax-highlit). :w applies, q cancels. Editable on @ anytime — there's no "final" commit.
c — commit
describe @, then jj new — seal this change and start the next. Pure convenience over d + n.
n — new
empty change atop @ (or atop the cursor change). The fresh canvas for the next unit of work.

§8 · BUILD CHECKLIST

Definition of done — the spine, in order

P0 · DATA LAYER
argv exec wrapper (sync + async + raw/NUL) · the §1 template reader + record/field split · change-id graph layout · refresh/debounce. Done = renders any repo & survives a mid-session rewrite.
P1 · SEE + NAME
status/log home with foldable files→hunks tree · describe buffer · new · commit · bare u. Done = navigate, describe, start changes, one-key undo.
P2 · ROUTE ★ — THE DIFF-EDITOR
the §3 launcher + RPC handshake · hunk-selection buffer · $right write-back · the four modes (split/squash-i/diffedit/restore) · edge cases. Done = split @ by selecting hunks, in your own buffer, no git-shim.
P3 · ROUTE + TRUST — absorb & the time machine
absorb preview + run · squash (s / S / m→s) · op-log buffer + restore + evolog. Done = absorb a sprawling diff, watch it in the op-log, undo it all. Ships the demo.
P6 (narrow) · THE GRAMMAR + SUPPORTING
which-key over the §2 keymap · counts + dot-repeat · statusline context · then the supporting cast (rebase gesture, bookmark, push/fetch). Done = the loop is discoverable from home row and curated work reaches a remote.
SHIP GATE   v1 is P0 → P3. At that point curate does one thing better than anything else in the ecosystem: move changes into the right commit. P6 and the supporting cast make it pleasant; they don't gate the identity. Everything else on the design board is a later chapter.
