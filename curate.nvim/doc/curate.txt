1. INTRODUCTION                                                   *curate-intro*

curate.nvim is a focused Jujutsu (jj) frontend for Neovim. It does one thing
well: move changes into the right commit. SEE -> ROUTE -> NAME -> TRUST.

Requires Neovim 0.11+ and jj 0.42+ on PATH.

==============================================================================
2. SETUP                                                          *curate-setup*

>lua
    require("curate").setup({
      log_revset = "@ | ancestors(@, 4) | trunk() | bookmarks()",
      refresh_debounce = 80,
      window = { split = "right" },     -- or { split = "float" }
      confirm_immutable = true,
      diff_editor_name = "curate",
    })
<
                                                              *curate.setup()*
require("curate").setup({opts})   Apply config, highlights, and keymaps.

3. COMMANDS                                                    *curate-commands*

:Curate [view]                                                       *:Curate*
    Open a curate surface. {view} is one of: status (default), log, oplog,
    evolog, process. With no argument, opens the status home.

==============================================================================
4. THE LOOP                                                        *curate-loop*

SEE     status home + log
ROUTE   absorb (A), squash (s/S), split (x) via the native diff-editor   <- ★
NAME    describe (d), commit (c), new (n)
TRUST   op-log (o), undo (u), op restore

ROUTE is the expertise: curate registers as jj's ui.diff-editor so split -i,
squash -i and diffedit open a native hunk-selection buffer. |curate-diffeditor|

5. KEYMAPS                                                      *curate-keymaps*

Lower-case = safe. UPPER-case = rewrites history. `.` repeats the last
rewriting gesture.

Home / log buffer ~
    <CR>   edit / expand under cursor      n   new change
    <Tab>  cycle fold                      d   describe
    A      absorb working copy             c   commit (describe + new)
    s      squash into parent / mark       S   squash interactively (hunks)
    x      split interactively (hunks)     =   restore from parent
    m      mark target                     r   rebase transient
    R      resolve conflicts (3-way)       b   bookmark menu
    f      sync menu (fetch/push)          e   revset workbench
    Z      power menu                      L   evolog
    o      op-log                          u   undo
    g      refresh    $  process buffer    ?   cheatsheet q  close

Diff-editor buffer ~
    <space>  toggle hunk    a  toggle file   A  toggle all
    [c ]c    prev/next hunk <CR> confirm     q  abort

Merge-editor buffer (3-way) ~
    l  left   r  right   L  left+right   R  right+left   b  base
    [c ]c  prev/next conflict   <CR> apply (all chosen)  q  abort

Op-log buffer ~
    <CR>  restore to op (append-only)   =  diff this op
    g- g+ undo/redo walk                L  evolog        u  undo

Revset workbench ~
    Line 1 is an editable revset; the log recomputes live below as you type.
    <CR>  jump to result (jj edit)      q  close

Annotate / blame ~
    Gutter (change-id + age) scroll-bound to the source file.
    <CR>  jump to the change that wrote the line     q  close

6. THE DIFF-EDITOR                                            *curate-diffeditor*

Pressing x or S launches jj with curate as the diff-editor. jj materialises
$left (before) and $right (after, writable) and blocks on a wait-shim. The
shim asks the running nvim to open the hunk buffer, then parks. On <CR> curate
rebuilds each $right file from only the selected hunks; jj records the diff.
On q it aborts and jj cancels. No temp git repo. See bin/curate-diff-shim.

The same handshake backs the merge-editor: R (resolve) registers curate as
jj's ui.merge-editor. jj passes $base/$left/$right (read-only) and an empty
$output; the 3-way buffer lets you pick a side per conflict and writes the
resolution into $output. One RPC mechanism, two editors. |curate-keymaps|

7. HIGHLIGHTS                                                *curate-highlights*

curate defines its highlight groups as |default| links to standard groups, so
it inherits whatever colorscheme you run (Catppuccin, Tokyo Night, gruvbox, …)
and re-links automatically on |ColorScheme|. Diff/state text groups link to the
foreground groups Added / Removed / DiagnosticError so they stay legible under
themes that make DiffAdd / DiffDelete background-only.

The diff- and merge-editors render syntax highlighting and the diff together:
code is treesitter-highlighted on the foreground while add/remove lives on the
line background (CurateAddedLine / CurateRemovedLine). Each side's file is parsed
as a whole and highlights are projected onto the rows by line number, so
multi-line strings/comments colorize correctly and injected languages (vimscript
in vim.cmd[[...]], fenced code in markdown, …) render in their own language.
Languages with no parser fall back to flat green/red. Toggle with the
`diff_syntax` option (default true).

On a modified line the diff-editor also emphasises just the tokens that changed
(intra-line word diff, CurateAddedText / CurateRemovedText). Toggle with the
`diff_word` option (default true).

Override any group; because the links use {default=true}, yours always wins: >
    vim.api.nvim_set_hl(0, "CurateChangeId", { fg = "#f5c2e7", bold = true })
